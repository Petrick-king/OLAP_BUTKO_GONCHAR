> и подключиться к нашей витрине было бы нечем.

## §3 Фильтр «Период с»

Параметр дашборда `date/single`, по умолчанию `2017-01-01`, привязан
ко всем четырём виджетам.

Проверка шла через **тот же endpoint, который вызывает UI**:
`POST /api/dashboard/<id>/dashcard/{dashcard}/card/{card}/query`.

| Значение фильтра | GMV_delivered | Позиций | Комментарий |
|------------------|--------------:|--------:|-------------|
| не задан → default `2017-01-01` | 13 181 027.13 | 109 880 | отрезан 2016 год |
| `2016-09-04` | **13 221 498.11** | **110 197** | весь период, совпадает с эталоном |
| `2018-01-01` | 7 218 125.12 | 60 324 | только 2018 |

Фильтр меняет **число**, а не только подпись. Это и есть проверка
«фильтр работает» из чек-листа.

## §5 Как воспроизвести с нуля

```bash
# 1. стенд + Metabase с драйвером ClickHouse
cd 01_З01_стенд_и_сырьё
docker compose --profile bi up -d
bash ./scripts/init_ch.sh
cd ..

# 2. данные и сводка
python 03_З03_витрина_duckdb/etl/build_duckdb.py
python 05_З05_elt_качество/etl/run_etl.py
python 06_З06_scd2_или_cut/etl/build_scd2.py
python 07_З07_загрузка_clickhouse/etl/load_clickhouse.py
python 09_З09_mv_витрина/etl/build_mv.py

# 3. дашборд
python 10_З10_дашборд_metabase/etl/setup_dashboard.py
```

Первый запуск Metabase требует мастера настройки (создать администратора).
На этом стенде он пройден один раз через API:

```
POST /api/setup  {token, user{email,password,...}, prefs{site_name}}
```

Учётка: `olap@example.com` / `Olist_2026!` (переопределяется
`MB_USER` / `MB_PASS` при запуске скрипта).

> Если поднимать Metabase **с нуля** (пустой `metabase_data`), мастер
> настройки надо пройти заново — скрипт `setup_dashboard.py` предполагает,
> что администратор уже существует и может залогиниться.

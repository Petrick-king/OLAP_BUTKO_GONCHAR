| № | Виджет | Тип | Источник данных | Вопрос паспорта |
|---|--------|-----|-----------------|-----------------|
| 1 | GMV_delivered за период (эталон) | карточка-число | `fact_sales` (**детальный факт**) | главная метрика |
| 2 | Позиций за период | карточка-число | `fact_sales` | знаменатель для среднего |

**Фильтр «Период с»** (тип `date/single`, по умолчанию `2017-01-01`)
привязан ко всем четырём виджетам через один и тот же template-tag
`{{start_date}}`.

---

## Почему главная метрика читает факт, а графики — сводку

Это не непоследовательность, а разделение ролей:

| Слой | Что читает | Почему |
|------|-----------|--------|
| Метрика (виджет 1) | **факт** | «правда метрики» живёт в детальной таблице; если сводка когда-нибудь разойдётся, эталон должен остаться верным |
| Графики (виджеты 3–4) | **сводку** | дашборд не должен пересчитывать 112 650 строк на каждое обновление экрана |

## Фильтр: как он устроен

В каждом виджете объявлен template-tag:

```json
{"name": "start_date", "type": "date", "default": "2017-01-01"}
```

В SQL он подставляется дата-литералом, поэтому обёрнут в `toDate(...)`:

```sql
WHERE order_date_key >= toDate({{start_date}})
```

На дашборде создан параметр `date/single` с `id = f1e2d3c4-…`, и в каждом
dashcard прописан mapping:

```json
{"parameter_id": "f1e2d3c4-…",
 "card_id": "<id карточки из metabase_setup.log>",
 "target": ["variable", ["template-tag", "start_date"]]}
```

Проверено через тот же endpoint, что использует UI
(`POST /api/dashboard/<id>/dashcard/…/card/…/query`):

| Значение фильтра | GMV_delivered |
|------------------|--------------:|
| не задан (default `2017-01-01`) | 13 181 027.13 |
| `2016-09-04` (начало данных) | **13 221 498.11** |
| `2018-01-01` | 7 218 125.12 |

Фильтр реально меняет число, а не просто рисуется.

## Ограничения, которые стоит знать

- **Фильтр — «с даты», а не диапазон.** Один параметр `date/single`
  привязывается к одному template-tag. Для диапазона нужно два тега
  (`start_date` / `end_date`) и два фильтра, потому что один параметр
  дашборда не раскладывается в два значения. Это сознательное упрощение.
- **Сводка не знает про статусы.** В неё попадают только `delivered`,
  поэтому «оборот по всем статусам» через неё не посчитать.
- **`orders` на дашборде не выводится** — эта мера не аддитивна по
  категориям 
- **Подключение — только ClickHouse.** В Metabase есть демо-база
  `Sample Database`, которую создаёт сам Metabase; к дашборду она
  отношения не имеет.

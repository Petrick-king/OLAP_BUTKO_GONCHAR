## Пять шагов подъёма

Ровно то, что нужно сделать на чистой машине.

Нужны: **Docker Desktop**, **Python 3.10+**, **Git Bash или WSL** (для
`init_ch.sh`). Пакеты: `pip install -r requirements.txt`.

```bash
# 1. Docker + стенд (ClickHouse обязателен, Metabase — профиль bi)
cd 01_З01_стенд_и_сырьё
docker compose --profile bi up -d
bash ./scripts/init_ch.sh          # база olist + пользователь olist
cd ..

# 2. Данные: DuckDB → ClickHouse
python 03_З03_витрина_duckdb/etl/build_duckdb.py
python 05_З05_elt_качество/etl/run_etl.py
python 06_З06_scd2_или_cut/etl/build_scd2.py
python 07_З07_загрузка_clickhouse/etl/load_clickhouse.py
python 09_З09_mv_витрина/etl/build_mv.py

# 3. Эталонный SQL метрики
#   04_З04_аналитический_sql/sql/canonical_metric.sql  →  13 221 498.11 BRL

# 4. Дашборд
#    первый раз: откройте http://localhost:3000 и создайте админа
#    (olap@example.com / Olist_2026! — или задайте MB_USER / MB_PASS)
python 10_З10_дашборд_metabase/etl/setup_dashboard.py
#   → скрипт печатает адрес: http://localhost:3000/dashboard/<id>

# 5. Если что-то красное
python 12_З12_интеграция_контура/etl/run_all.py
```

Шаг 5 — диагностика: он идёт по всем этапам, останавливается на первом
упавшем и печатает его вывод. Не нужно угадывать, что сломалось.

## Путь данных вслух (1–2 минуты)

> Исходный файл — `raw data/olist_*.csv`, девять файлов Olist за 2016–2018.
> Их читает `build_duckdb.py`: восемь проверок качества **до** загрузки
> (пустые ключи, сироты, отрицательные деньги, факт = сырьё), затем
> загрузка **dim → fact** — так требует `elt_checks.md`.
> Одна строка факта `fact_sales` = **одна позиция одного заказа**.
> Главная мера — **`SUM(amount)` по заказам со статусом `delivered`**,
> это `GMV_delivered` = **13 221 498.11 BRL**.
>
> Дальше витрина переезжает в **ClickHouse**: `MergeTree`,
> `PARTITION BY toYYYYMM(order_date_key)` — 24 месячных куска,
> `ORDER BY (order_date_key, order_status, seller_id, …)` — дата и статус
> первыми, потому что все отчёты фильтруются по периоду и статусу.
> `ORDER BY` здесь — **порядок хранения и пропуск гранул, а не уникальность**:
> `EXPLAIN indexes = 1` показывает, что на фильтре по одному дню читается
> 1 гранула из 29.
>
> Под график собрана сводка `mv_gmv_day_category` — **одна строка = день ×
> категория**, 112 650 строк факта схлопываются в 18 808. Сумма сводки
> равна сумме факта до копейки.
>
> Наверху — Metabase: четыре виджета поверх ClickHouse, фильтр «Период с».
> Карточка метрики читает **детальный факт** (это эталон), графики —
> **сводку** (это скорость). Сверка З11 прогоняет одно и то же условие
> через SQL, сводку, карточку и дашборд — все четыре дают одно число.

## Исключения: что всё-таки делается руками

Честный список — задание просит именно его.

| Шаг | Почему руками | Цена |
|-----|---------------|------|
| Первый запуск Metabase (мастер настройки, создание администратора) | Metabase не даёт создать первого пользователя без setup-token | один раз на чистом стенде; скрипт З10 предполагает, что админ уже есть |
| `bash` для `init_ch.sh` | скрипт написан на bash | Git Bash или WSL; либо те же `docker exec`-команды вручную |
| Скачивание драйвера ClickHouse для Metabase | драйвер не входит в образ и лежит в репозитории | уже скачан и лежит в `01_З01_стенд_и_сырьё/metabase-plugins/` |
| Запуск Docker Desktop | Windows-специфика | без него не поднимется стенд; `run_all.py` скажет об этом первой строкой |

Всё остальное — скрипты из репозитория.

## Зачем

Собрать проект так, чтобы преподаватель за несколько команд понял, **с чего начать**, и увидел цепочку от файлов до числа на дашборде.

## Что сделать

1. Пройти [[чеклист_зачёта_канон|чеклист зачёта]].
2. Дописать README.
3. Актуализировать список отказов и короткий устный рассказ, как данные доходят до экрана.

---

## Ход работы

### 1. Чеклист

Пройдите пункты чеклиста. Дыры закройте или перенесите в `cut.md` с понятной ценой отказа.

### 2. README как точка входа

Не больше пяти шагов подъёма:

1. как запустить Docker и стенд;
2. как загрузить данные;
3. где эталонный SQL метрики;
4. как открыть дашборд;
5. куда смотреть, если что-то красное.

### 3. Актуальный `cut.md`

Уберите пункты из З02, которых уже нет в проекте. Оставьте только реальные отказы.

### 4. Прогон «с нуля»

По возможности поднимите проект на чистом стенде. Если что-то руками — честный список исключений в README.

### 5. Устный путь данных (на 1–2 минуты)

Абзац в README, который потом говорите вслух:

> Исходный файл → скрипт загрузки и проверки → справочники и факт в ClickHouse (почему такой порядок полей в сортировке) → эталонный SQL метрики → карточка на дашборде с теми же фильтрами. Одна строка факта = … Главная мера = …
